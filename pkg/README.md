# Releasing

1. Set `version` in the root `Cargo.toml`, run `DFDU_UPDATE_ASSETS=1 cargo test -p dfdu --test assets` (the man pages carry the version) and commit.
2. Tag and push: `git tag v0.2.0 && git push origin v0.2.0`. `.github/workflows/release.yml` (generated by `dist generate` from `dist-workspace.toml`; do not edit it by hand) builds the five archives, creates the GitHub release with the installers and checksums, and pushes the Homebrew formula to `jordond/homebrew-tap`. That push needs a `HOMEBREW_TAP_TOKEN` secret: a token with write access to the tap repository.
3. `scripts/package-manifests.sh 0.2.0` writes the Scoop, winget and AUR manifests filled with the release's checksums to `target/pkg/0.2.0`. Submit them by hand: the Scoop manifest to a bucket, the winget manifests as a pull request to `microsoft/winget-pkgs` (`manifests/j/jordond/dfdu/0.2.0/`), and the PKGBUILD to the `dfdu-bin` AUR repository (with `makepkg --printsrcinfo > .SRCINFO`).

The Nix flake (`flake.nix`) builds from source at any commit and needs nothing per release.

Before a release, check on a clean machine that each channel installs and runs (`dfdu --version`, `dfdu scan ~`).
