# Releasing

1. `cargo xtask release check` runs the checks a release needs on top of CI (assets current, advisories, `dist plan`). Then `cargo xtask release bump 0.2.0 --commit` sets `version` in the root `Cargo.toml`, updates `Cargo.lock` and the assets (the man pages carry the version), commits and tags `v0.2.0`.
2. Push the commit and tag: `git push origin HEAD v0.2.0`. `.github/workflows/release.yml` (generated by `dist generate` from `dist-workspace.toml`; do not edit it by hand) builds the five archives, creates the GitHub release with the installers and checksums, and pushes the Homebrew formula to `jordond/homebrew-tap`. Then `gui-release.yml` adds the GUI's installers (dmg, app.tar.gz, AppImage, deb, NSIS, zip) and `gui-sha256.sum` to the release and pushes the `dfdu-gui` cask to the tap. That push needs a `HOMEBREW_TAP_TOKEN` secret: a token with write access to the tap repository. `publish-aur.yml` fills the PKGBUILDs in `pkg/aur/` (`dfdu-bin` from the release's archives, `dfdu` from the tag's source, `dfdu-git` from the latest commit), builds and installs `dfdu-bin` and `dfdu` in an Arch Linux container, and pushes each with its `.SRCINFO` to its AUR package. `dfdu-git` is pushed only when its PKGBUILD changes, since its version comes from `pkgver()` at build time. That push needs an `AUR_SSH_PRIVATE_KEY` repository secret: the private half of an SSH key added to the maintainer's AUR account. Prereleases are not published to the AUR.
3. `cargo xtask release manifests 0.2.0` (needs `gh`) writes the Scoop, winget and AUR manifests filled with the release's checksums to `target/pkg/0.2.0`, with the GUI's Scoop and winget manifests (`dfdu-gui`, `jordond.dfdu-gui`) when the release has GUI checksums. Submit them by hand: the Scoop manifest to a bucket, the winget manifests as a pull request to `microsoft/winget-pkgs` (`manifests/j/jordond/dfdu/0.2.0/`). The AUR PKGBUILDs are published by the release workflow; to publish one by hand, run `.github/scripts/aur-push.sh PKGNAME DIR VERSION` on a directory holding it and its `makepkg --printsrcinfo > .SRCINFO`.

The Nix flake (`flake.nix`) builds from source at any commit and needs nothing per release.

Before a release, check on a clean machine that each channel installs and runs (`dfdu --version`, `dfdu scan ~`).
