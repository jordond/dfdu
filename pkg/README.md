# Releasing

1. `cargo xtask release check` runs the checks a release needs on top of CI (assets current, advisories, `dist plan`). Then `cargo xtask release bump 0.2.0 --commit` sets `version` in the root `Cargo.toml`, updates `Cargo.lock` and the assets (the man pages carry the version), commits and tags `v0.2.0`.
2. Push the commit and tag: `git push origin HEAD v0.2.0`. `.github/workflows/release.yml` (generated by `dist generate` from `dist-workspace.toml`; do not edit it by hand) builds the five archives, creates the GitHub release with the installers and checksums, and pushes the Homebrew formula to `jordond/homebrew-tap`. That push needs a `HOMEBREW_TAP_TOKEN` secret: a token with write access to the tap repository.
3. `cargo xtask release manifests 0.2.0` (needs `gh`) writes the Scoop, winget and AUR manifests filled with the release's checksums to `target/pkg/0.2.0`. Submit them by hand: the Scoop manifest to a bucket, the winget manifests as a pull request to `microsoft/winget-pkgs` (`manifests/j/jordond/dfdu/0.2.0/`), and the PKGBUILD to the `dfdu-bin` AUR repository (with `makepkg --printsrcinfo > .SRCINFO`).

The Nix flake (`flake.nix`) builds from source at any commit and needs nothing per release.

Before a release, check on a clean machine that each channel installs and runs (`dfdu --version`, `dfdu scan ~`).
